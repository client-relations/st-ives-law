# Nautilus Law Group — Estate Planning Questionnaire
## Full Build Prompt for Claude Code on Replit

---

## PROJECT OVERVIEW

Build a production-ready multi-part estate planning client questionnaire as a React web application. This is a real law firm intake form that collects client data across 4 parts and submits the full payload via webhook to Make.com on final submission.

---

## TECH STACK

- **React 18** with Vite (not Create React App)
- **No UI library** — all styling is custom CSS-in-JS (inline styles) using a centralised design token object
- **No TypeScript** — plain JavaScript only
- **No backend** — purely frontend, webhook POST on submission
- Single page application, no routing needed

---

## FORM LOGIC — FULL SPECIFICATION

### Global Rules
- State is managed at the top level in `App.jsx` using `useState` for `aData`, `bData`, `cData`, `dData`
- All state updates use immutable patterns (spread operator)
- Each part has its own custom hook (`usePartA`, etc.) that returns: `{ pages, pg, setPg, total, pct, title, renderPage }`
- Pages within each part are dynamically filtered based on prior answers (see conditional logic below)
- Navigation: Back / Next buttons. "Next" on final page of a part advances to the next part tab
- A left sidebar shows all page titles for the current part; visited pages show a ✓ prefix

---

### PART A — Identity, Family & Assets

**Page: Welcome**
- Engagement type: Single Client / Couple (Joint Matter) / Couple (Separate Matters) — radio, required
- State/territory: NSW / VIC / QLD / SA / WA / TAS / NT / ACT — select, default NSW
- Referral source: select with options
- If referral source starts with "Referral": show referrer first name, last name, firm, phone, email
- Contact preference: Email / Phone Call / Video Call / Post — radio
- Urgent: Yes / No — radio; if Yes, show urgency detail textarea

**Page: C1 — Personal Details**
All fields: Title (select), First, Middle, Last, Preferred name, Previous legal names, DOB (date, required), Place of birth, Gender (select), Citizenship, Permanent Resident (radio), TFN (tel, show warning about encryption), Email (required), Mobile (required), Home phone, Residential address (required), "Is postal address same?" radio — if No show postal address field, Occupation, Employer, Relationship status (select), Date of relationship (date), Prior relationships (radio) — if Yes show details + children from prior relationship, Religion, Interpreter required (radio), Capacity (radio with 3 options) — if not "No — full capacity" show detail textarea

**Page: C2 — Personal Details**
Shown only if engagement type is Couple. Identical fields to C1.

**Page: Children**
- Has children: Yes/No radio
- If Yes: count of joint children (number) → dynamic list; each child: Title, First, Middle, Last, DOB, Relationship type (select: Biological/Adopted/Step-child/Other), Special needs (select)
- Has grandchildren: Yes/No → if Yes show detail
- Other financial dependants: Yes/No → if Yes show detail

**Page: Family Background**
- C1 father name, father living (radio)
- C1 mother name (incl maiden), mother living (radio)
- Family provision claim risk: Yes/No/Unsure → if Yes show detail

**Page: Disclosure Preference**
- Radio: "full" / "summary" / "discuss"
- Label descriptions for each option
- This controls which financial pages appear

**Conditional financial pages (shown only if disclosure = "full"):**

**Page: C1 — Property**
Count of properties → dynamic list; each: address, type (select), ownership (select: Sole/Joint Tenants/Tenants in Common/Other), estimated value, year purchased

**Page: C1 — Financial Assets**
Bank accounts: count → list; each: institution, account type (select), balance, ownership (Sole/Joint)
Shares/investments: count → list; each: platform, description, value
Crypto: Yes/No → if Yes detail textarea
Foreign assets: Yes/No → if Yes detail textarea

**Page: C1 — Superannuation**
Count → list; each: fund name, ABN, balance, BDBN status (select: Yes-lapsing/Yes-non-lapsing/No/Unsure), nominated beneficiary, BDBN expiry date

**Page: C1 — Other Assets & Liabilities**
Other assets: textarea
Mortgages: count → list; each: lender, secured property, balance, rate type (select)
Personal loans: count → list; each: lender, type (select), balance
Personal guarantees: Yes/No → if Yes detail textarea

**If couple, repeat C2 versions of all four financial pages**

**Shown only if disclosure = "summary":**

**Page: Financial Summary**
Table with rows: Total real property, Total bank/cash, Total shares/investments, Total other assets, Total mortgages/debts
Columns: Client 1, Client 2 (if couple), Joint

**Page: Part A Summary**
Green completion banner

## REUSABLE COMPONENTS

### `Field.jsx`
Props: `label`, `type` (text/email/tel/date/number/textarea/select/radio), `opts` (array for select/radio), `value`, `onChange`, `required`, `placeholder`, `rows`, `sub` (subtitle label), `warn` (warning message shown above input in amber box)
Required fields show a red asterisk. All inputs use the design token border/background.

### `SectionHeader.jsx`
Props: `icon` (emoji), `title`, `sub`
Renders icon + Georgia serif title + optional subtitle + horizontal rule

### `AdviceBox.jsx`
Props: `title`, `children`
Collapsible panel with amber styling. Default collapsed. Toggle arrow.

### `InfoBox.jsx`
Props: `children`, `color`, `border`
Non-collapsible info panel. Defaults to slate/pale blue palette.

### `SectionLabel.jsx`
Props: `text`
Small teal label bar used to separate sub-sections within a page

### `PersonList.jsx`
Props: `countLabel`, `listKey`, `countKey`, `D`, `update`, `noun`, `showDOB`, `showNick`, `showAgreed`, `showAddress`
Renders a number input for count, then a dynamic list of person cards. Each card: Title, First, Middle, Last, Preferred name (if showNick), DOB (if showDOB), Relationship, Email, Mobile, Address (if showAddress), "Has agreed to act?" radio (if showAgreed)

### `DistributionScenario.jsx`
Props: `prefix`, `D`, `update`, `scenLabel`, `clientName`
See full logic in Part C spec above

## DEPLOYMENT ON REPLIT

After building:
1. Run `npm run build` — Vite outputs to `dist/`
2. In Replit, set the run command to: `npx serve dist`
3. Replit will assign a public `.replit.app` URL automatically
4. For a custom domain: go to Replit → Deployments → Custom Domain → add your domain and point DNS CNAME to `<your-repl>.replit.app`

## IMPORTANT CONSTRAINTS

- No localStorage or sessionStorage — all state in React useState only
- No external UI libraries (no MUI, no Ant Design, no Chakra)
- No TypeScript
- All colours and fonts via the centralised `C` token object — no hardcoded hex values anywhere else in the codebase
- The webhook fires ONCE only — on mount of the ThankYou component — with a loading/success/error state machine
- The form must be fully functional on mobile (responsive, minimum 360px width)
- All dynamic lists (PersonList, properties, bank accounts etc.) use array index as key only as a last resort — prefer stable keys where possible
- Percentages in residuary beneficiary distribution should soft-validate to sum to 100% and show a warning if they don't (but do not block submission)
